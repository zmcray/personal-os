# Formatting Rules

These rules apply across all skills and content. Enforce universally.

## Em Dashes

NEVER use em dashes in any artifacts, documents, or outputs. This includes:
- .md files
- .docx documents
- .pptx presentations
- .pdf files
- Chat output
- Code comments

Alternatives:
- Use commas for loose clauses: "The system, which was built in Phase 2, launched on schedule."
- Use semicolons to connect related ideas: "Format matters; specificity matters more."
- Use periods to break sentences: "The pattern is clear. Replies without data underperform."
- Use "..." for pauses: "This gets interesting... most people miss it."

## Numbers in Copy

- Use numerals, not words: "3 posts" not "three posts"
- Be specific: "50+ likes" or "1-3 sentences" not "many" or "several"
- Include context: "30% higher engagement" not just "higher engagement"

## Lists and Bullets

- Use docx-js numbering for Word documents, never unicode bullet characters
- Markdown: Use standard markdown bullets (- or *)
- Bold leads: For step lists, use "**Bold lead:** Explanation" format
- One sentence per bullet unless additional context is critical

## Callout Boxes

In Word documents (doc-that skill):
- Use left border accent in #F39C12 (amber)
- Italic text for content
- Use for critical gotchas and warnings at point of impact

## Tables

In Word documents:
- Dark header row (#2E4057) with white text
- Light borders (#CCCCCC)
- Use DXA widths for sizing
- Header should be bold

## Headings Hierarchy

- H1 (#): Document title or main skill name
- H2 (##): Major sections (Input, Output, Steps, Rules, etc.)
- H3 (###): Subsections
- Keep hierarchy consistent across documents

## Line Breaks and Spacing

Markdown:
- Use `---` for horizontal dividers between major sections
- Single blank line between paragraphs
- Double blank line before new major section

Word:
- 6pt spacing before headings
- 3pt spacing after headings
- Single spacing within paragraphs
